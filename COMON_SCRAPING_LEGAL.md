# Парсинг comon.ru / Finam: есть ли явный запрет?

Краткие выводы по проверке открытых правил сервиса (на дату составления заметки).  
**Это не юридическая консультация.**

## Краткий ответ

**Явного запрета парсинга** (формулировок вроде «запрещается парсить / скрапить / автоматически собирать данные») в доступных публичных правилах [comon.ru](https://www.comon.ru) / документации Finam **не найдено**.

Отсутствие такого пункта **не означает разрешение**. ToS могут меняться; возможны иные договоры (ЛК, оферты автоследования), не разобранные здесь построчно.

## Что проверено

| Источник | Результат |
|----------|-----------|
| [Общие правила использования сайта](https://docs.comon.ru/general-information/rules/) | Запреты про виртуалов, флуд, спам, оскорбления, символику Финама и т.п. Слов «парсинг», «скрапинг», «автоматизированный сбор», «робот» (в смысле скрейпера) **нет** |
| [Защита информации](https://docs.comon.ru/general-information/information-security/) | Про персональные данные и cookies; **явного запрета скрейпинга нет** |
| Поиск по `docs.comon.ru` | Отдельного пункта про парсинг не видно |
| Finam Trade API | Официальная автоматизация **торговли** — это **не** разрешение парсить веб-интерфейс / недокументированные endpoint’ы comon.ru |

### robots.txt

`https://www.comon.ru/robots.txt` при проверке из скрипта отдавал **403 Forbidden** (антибот / WAF), содержимое прочитать не удалось.  
`https://docs.comon.ru/robots.txt` — **404**.

Технические ограничения доступа ≠ замена пользовательского соглашения, но показывают, что автоматические запросы сайт может резать.

## Выводы для проекта

1. **Явного текстового запрета парсинга** в открытых правилах comon на момент проверки **нет**.
2. Риск остаётся из‑за:
   - использования **недокументированного** HTTP API (`/api/v1/strategies/{id}/profit`);
   - массового обхода UI через Selenium;
   - нагрузки на сервис и антибот-защиты;
   - возможного изменения правил без уведомления.
3. Перед публичной выкладкой и массовым распространением см. также [PUBLISHING_RISKS.md](PUBLISHING_RISKS.md).

## Рекомендации

- Не утверждать в README, что Finam «разрешил» парсинг.
- Можно указать факт: *в открытых общих правилах comon явного запрета парсинга не обнаружено; использование — на свой риск*.
- Соблюдать разумные лимиты запросов; не позиционировать инструмент как обход защиты сайта.
- При сомнениях — запрос в поддержку Finam/comon или консультация юриста.
