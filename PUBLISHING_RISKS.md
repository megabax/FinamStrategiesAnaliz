## Высокий риск

### 1. Юридический: скрейпинг + недокументированный API

Проект массово парсит [comon.ru](https://www.comon.ru) (Selenium) и обращается к недокументированному endpoint:

`GET https://www.comon.ru/api/v1/strategies/{number}/profit`

Возможные последствия:

- претензии по пользовательскому соглашению (ToS) / несанкционированному доступу к данным;
- при активном распространении чужие запуски увеличат нагрузку на сайт → выше шанс блокировок и внимания владельца сервиса;
- для работодателя это может выглядеть как «кандидат обходит ограничения чужого сервиса».

**Смягчение:**

- ✅ в README: личный / исследовательский pipeline, не коммерческий сервис; вежливое использование; соблюдать правила сайта
- ✅ API описан как неофициальный (undocumented), без SLA, не Finam Trade API; запасной путь — Selenium
- ✅ не позиционировать проект как «как обойти Finam / comon»  
  — тон README нейтральный, есть ссылка на правовые заметки

### 2. Инвестиционный дисклеймер

`analiz/rank.py` считает Sharpe, CAGR и ранжирует стратегии.

Без оговорок это воспринимается как инвестиционная рекомендация. Репутационный риск: «по вашему рейтингу потерял деньги».

**Смягчение:**

- ✅ крупный дисклеймер в README: не инвестиционный совет; данные могут быть неточны; прошлые результаты не гарантируют будущих

## Средний риск

### 3. Утечка инфраструктуры

В коде встречалось имя хоста `MEGABAX\SQLEXPRESS`. Реальных паролей в репозитории нет (placeholders + Windows Authentication), но имя машины / ПК лишнее. Даже после правки hostname может остаться в git history.

**Смягчение:**

- ✅ вынести строку подключения в `.env` / переменные окружения — `DATABASE_URL` или `MSSQL_*` (`lib/env.py`)
- ✅ в репозитории — только `localhost` или явные placeholders (`.env.example`, `alembic.ini`)
- ❌ rewrite history / чистый репозиторий — не делалось (старые коммиты могут содержать hostname)

### 4. Репутация кода vs портфолио

**Сильные стороны:** Alembic, pytest, метрики риска, CLI, верификация данных.

**Слабые для HR / техскрининга:** хардкод параметров БД, дубли скриптов (`test.py` vs автотесты), каталог `other/`, опечатки в сообщениях коммитов, смешанный стиль.

**Смягчение перед выкладкой:**

- ✅ README: что умеет проект, как запустить, ограничения  
  — есть конвейер, метрики, ссылки на риски / парсинг / вежливое использование
- 🟡 убрать или не публиковать мусорные скрипты  
  — черновики перенесены в `other/`, но каталог и `SQLDemo.py` всё ещё в репо
- 🟡 secrets только через env  
  — `.env` в `.gitignore`; Chrome и **БД** через env; history git может ещё содержать старый hostname
- ❌ 1–2 скриншота рейтинга / графика  
  — нет (и `*.png` в `.gitignore`)

### 5. Злоупотребление третьими лицами

Публичный инструмент массовой выгрузки истории: кто-то может гонять его агрессивно; косвенно «ваш» проект.

**Смягчение:**

- ✅ разумные задержки / не перегружать сервер — в README блок «Вежливое использование»
- ✅ не рекламировать параллельный «штурм» comon — прямо сказано не запускать частые и параллельные запросы
- 🟡 формулировка «на свой риск» — есть в README
- ❌ LICENSE (MIT / Apache и т.п.) — файла лицензии нет
