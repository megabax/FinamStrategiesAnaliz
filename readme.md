# FinamStrategiesAnaliz

Сбор и анализ данных об инвестиционных стратегиях с [comon.ru](https://www.comon.ru/strategies/) (Finam). Проект использует Selenium для парсинга, SQLAlchemy и MSSQL для хранения, Alembic для миграций.

## Быстрый старт

```bash
python -m venv venv
venv\Scripts\activate.bat
pip install -r requirements.txt   # если есть; иначе — зависимости из окружения
alembic upgrade head
```

Скопируйте `.env.example` в `.env` и при необходимости настройте Chrome.

## Конвейер данных

| Скрипт | Назначение |
|--------|------------|
| `run.py` | Загрузка **карточек стратегий** с comon.ru → таблица `strategies` |
| `load_history.py` | Загрузка **дневной истории** доходности → таблица `history` |
| `test.py` | Массовая **проверка** накопленной доходности (БД vs сайт) |
| `test_intervals.py` | Проверка по **интервалам** для одной стратегии |
| `lib/verify.py` | Общая логика верификации после загрузки истории |

### Загрузка списка стратегий

```bash
python run.py              # все страницы, обновление существующих
python run.py --only-new   # только новые стратегии
```

### Загрузка истории

```bash
python load_history.py                                    # все активные стратегии, до вчера
python load_history.py -n 112741                          # одна стратегия
python load_history.py -n 109075 --end-date 2025-11-26
python load_history.py --reload -n 109075 --from-date 2025-11-14 --end-date 2025-11-26
python load_history.py --clear-and-load -n 109075 --from-date 2024-01-01 --end-date 2024-12-31
```

Архивные стратегии (`archived = 1`) пропускаются при массовой загрузке; для них нужен явный `-n`.

### Проверка данных

```bash
python test.py
python test_intervals.py -n 112741 -d 200 --from-date 2024-01-01 --to-date 2024-12-31
```

## Что есть для анализа (и чего нет)

### Есть

**Метаданные с сайта** — при загрузке карточек сохраняются `annual_income`, `subscribers`, `min_summa`, тип стратегии. Это данные comon.ru, без собственного расчёта рейтинга.

**Проверка качества данных** — `test.py`, `test_intervals.py`, `lib/verify.py` отвечают на вопрос «данные в БД совпадают с сайтом?», а не «стратегия выгодная?».

**Черновики анализа:**

| Файл | Содержание |
|------|------------|
| `analiz/stathist.py` | График дневного `%` дохода, скользящее среднее (100 дней), полосы ± std для одной стратегии |
| `str_test.py` | Рост портфеля по истории vs случайная модель (normal); захардкожен `strategy_id=1` |
| `lib/nnlib.py` | Заготовка LSTM для прогноза; не интегрирована в проект |
| `query.sql` | `avg(perc_income_day)`, `stdev(perc_income_day)` по `strategy_id` |
| `infoquery.sql` | Min/max даты истории по стратегиям |

### Нет

- рейтинга / score / ranking стратегий;
- метрик риска: Sharpe, Sortino, max drawdown, recovery time;
- сравнения стратегий между собой;
- фильтра «лучшие для инвестиций»;
- готового отчёта по привлекательности.

**Итог:** проект сейчас — **конвейер сбора и верификации данных**. Оценка инвестиционной привлекательности не реализована; есть только зачатки (`stathist.py`, `str_test.py`, `query.sql`).

## С чего начать оценку привлекательности

Рекомендуемый порядок — от простого SQL к полноценному модулю.

### Шаг 1. Базовые метрики по истории (SQL или Python)

На основе `history.perc_income_day` для каждой стратегии за выбранный период:

- **CAGR** — совокупная и годовая доходность;
- **волатильность** — std дневных доходностей (годовая через √252);
- **max drawdown** — максимальная просадка от пика equity-кривой;
- **доля положительных дней** — простой показатель стабильности.

Можно расширить `query.sql` или добавить `analiz/metrics.py` с расчётом из БД через pandas.

### Шаг 2. Risk-adjusted метрики

- **Sharpe** = (доходность − безрисковая ставка) / волатильность;
- **Sortino** — только downside-волатильность;
- **Calmar** = CAGR / |max drawdown|.

Это даёт первый объективный рейтинг «доходность на единицу риска».

### Шаг 3. Сводная таблица / CSV-рейтинг

Скрипт `analiz/rank.py` (или аналог):

- вход: период (`--from-date`, `--to-date`), опционально фильтр по `kind`, `min_summa`;
- выход: CSV в `reports/` с колонками strategy, CAGR, vol, max_dd, Sharpe, subscribers;
- сортировка по Sharpe или Calmar;
- исключение архивных и стратегий с короткой историей (например, &lt; 252 торговых дней).

### Шаг 4. Визуализация

Развить `analiz/stathist.py`:

- equity curve и drawdown chart;
- сравнение нескольких стратегий на одном графике;
- опционально — сравнение с `annual_income` с карточки (расхождение факт vs заявленное).

### Шаг 5. Скоринг (опционально)

Взвешенная формула, например:

```
score = w1 * norm(Sharpe) + w2 * norm(Calmar) − w3 * norm(max_drawdown) + w4 * norm(subscribers)
```

Веса и пороги — настраиваемые. Нейросеть (`nnlib.py`) имеет смысл только после стабильного baseline на классических метриках.

### Практическая рекомендация

**Начать с шага 1–3:** один модуль `analiz/metrics.py` (расчёт метрик) + CLI `analiz/rank.py` (таблица топ-N за последний год). Данные уже в БД; верификация через `test.py` даёт уверенность в качестве входных рядов.

Пример первой команды после реализации:

```bash
python analiz/rank.py --from-date 2024-01-01 --to-date 2024-12-31 --top 20 --output reports/rank_2024.csv
```
